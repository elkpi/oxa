# v2.4.1 — Anthropic cache_control 跨面遗漏 Detail 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Anthropic `cache_control` 断点跨面（→Chat Completions / →Responses）产生的 `unmapped-field` 遗漏携带自描述 detail，spec 固化该语义，五语言 lockstep 发布 v2.4.1。

**Architecture:** spec/15 已有 `NativeAnnotation.omission{field,reason,detail}` 机制且编码侧已逐字段抄录；本改动只在五个语言的 Anthropic 解码器为 `cache_control` 的 omission 填充统一 detail 常量，不动 kind、不动 wire、不动 loss 数量。规范 → 向量 → 实现 按项目契约顺序落地。

**Tech Stack:** Go / TypeScript / Python / Rust / C++；黄金向量 `vectors/`（manifest 由 veccheck 生成）。

**Spec:** spec/15-native-request-options.md（§3.2、§4、§4.1）；共识记录见本计划头部结论。

## Global Constraints

- detail 常量（五语言逐字节一致，公开契约）：
  `anthropic-native cache breakpoint; the target face has no cache_control representation`
- 仅 `field="cache_control"` 且 `reason="unmapped-field"` 的 NativeOmission 获得该 detail；`unmapped-value`（未知 ttl/type 的 "cache_control type must be ephemeral" 等）与 thinking 系 detail（"budget approximated"）一律不变。
- wire 输出字节不变；loss 的 path/field/reason/数量不变；Anthropic→Anthropic 回转仍无损。
- 每语言用一个命名常量，禁止五处重复字面量。
- 提交粒度：spec、vectors、五语言、docs、chore(.superpowers)、release 各自独立 commit（cherry-pick 友好）。
- 向量计数断言 317 → 318（python/tests/test_vectest.py:46、rust/crates/oxa-vectest/tests/load.rs:116）。
- 新增向量后必须 `go run ./cmd/veccheck -root .. -write-manifest`（在 go/ 下执行）。

## Review Focus

- 非 Anthropic 来源或无 omission 的路径不受影响（detail 为 omitempty/可选）。→ 钉子：Task 2 既有非 cache 向量全部原样通过。
- Anthropic→Anthropic 回转向量不得出现 detail 或新 loss。→ 钉子：Task 2 `anthropic-to-anthropic-native-request.json` 不含新 detail 的 loss 断言（仅 IR 中间态 omission 加 detail）。
- thinking budget 的 degraded detail 保持 "budget approximated"。→ 钉子：Task 2 跑 budget 系向量。
- 未知 ttl/type 的 cache_control 仍走 unmapped-value + 原 detail，不误加新 detail。→ 钉子：Task 2 `native-cache-unknown-ttl-request-to-ir.json`。
- detail 若进了期望向量而某语言未实现，该语言向量测试必须红。→ 钉子：Task 2 完成后、Task 3 之前跑 Go 向量测试确认失败（红-绿验证）。
